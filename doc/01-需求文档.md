## 1. 文档说明

### 1.1 编写目的

本文档定义 MZ-KnowBase 的产品边界、用户角色、业务规则、功能需求、非功能需求和验收标准。研发、测试和部署均以本文档作为需求基线；技术实现细节见《技术文档》，实施顺序与任务拆分见《开发计划》。

### 1.2 产品范围

MZ-KnowBase 面向中小企业，提供多租户的私有知识库服务，覆盖以下闭环：

1. 租户开通、用户登录、角色与数据权限管理。
2. 文件夹与文档的创建、编辑、版本管理、搜索和回收站。
3. 文档附件的分片上传、下载与受控访问。
4. 飞书文档、飞书多维表格的全量与增量同步。
5. 文档切片、向量化、全文索引与混合检索。
6. 基于私有文档的 RAG 问答、流式输出、引用溯源和多轮会话。
7. 同步失败、索引失败和系统事件的通知与审计。

### 1.3 术语

| 术语 | 定义 |
| --- | --- |
| 租户（Tenant） | 相互隔离的企业客户空间。所有业务数据必须归属唯一租户。 |
| 知识库文档 | 平台内创建的 Markdown 文档，或从飞书同步而来的只读文档。 |
| 文档片段（Chunk） | 文档按标题和长度策略切分后的最小检索单元。 |
| Embedding | 将文本转换为向量表示的过程或结果。 |
| RAG | 检索增强生成。先召回文档片段，再让大模型基于片段回答。 |
| 权限感知检索 | 在召回后、送入大模型前，按当前用户文档权限过滤片段。 |
| 全量同步 | 首次同步或人工重建时，拉取指定飞书空间内的全部受支持资源。 |
| 增量同步 | 仅拉取上次成功同步时间之后发生变更的资源。 |
| 索引就绪 | 文档已完成切片、向量化和全文索引，可被 AI 问答与检索使用。 |

### 1.4 优先级定义

| 级别 | 含义 | 发布要求 |
| --- | --- | --- |
| P0 | 核心闭环，缺失则产品不可用 | MVP 必须完成 |
| P1 | 重要增强，明显提升可用性或可运营性 | V1.1 完成 |
| P2 | 长期能力，首版不阻塞交付 | 按资源安排 |

## 2. 产品概述

### 2.1 背景与问题

中小企业的产品文档、技术文档和需求资料通常分散在飞书、网盘、聊天记录和个人电脑中，存在以下问题：

1. 资料入口分散，新成员难以快速找到准确信息。
2. 关键词搜索无法理解自然语言问题，历史文档难以复用。
3. 通用大模型不了解企业私有资料，直接回答容易产生幻觉。
4. 企业资料存在权限边界，普通 RAG Demo 往往忽略权限过滤，存在泄密风险。
5. 飞书等 SaaS 工具与企业内部系统割裂，文档无法自动进入知识库。

### 2.2 产品定位

**面向中小企业的、可私有化部署的多租户知识库与 RAG 问答平台。**

产品以“文档沉淀 + 权限控制 + 可溯源 AI 问答”为核心，不追求通用办公套件能力，重点解决企业资料“找得到、问得准、答得安全”的问题。

### 2.3 目标用户

| 角色 | 典型画像 | 核心诉求 |
| --- | --- | --- |
| 企业管理员 | 行政、IT 或团队负责人 | 开通租户、管理用户与角色、控制资料访问范围 |
| 知识管理员 | 产品经理、技术负责人、运营 | 维护目录、同步飞书资料、检查索引与同步状态 |
| 普通成员 | 研发、销售、客服、新员工 | 搜索资料、阅读文档、向 AI 提问并获得出处 |
| 外部访客 | 合作伙伴或临时成员 | 通过受控分享链接阅读指定文档，不进入 AI 检索范围 |
| 平台运维 | 部署与维护人员 | 查看健康状态、处理同步与索引失败、完成升级和备份 |

### 2.4 核心价值

1. **统一沉淀**：平台文档与飞书资料进入同一知识目录。
2. **安全问答**：AI 只基于当前用户有权访问的内容回答。
3. **答案可查**：每条回答提供文档标题、片段与原文入口。
4. **持续更新**：文档变更后自动重建索引，保证问答内容不过期。
5. **私有部署**：业务数据、向量数据和模型调用均可留在企业内网。

### 2.5 产品目标与成功指标

| 目标 | 指标 | 首版目标 |
| --- | --- | --- |
| 降低知识查找成本 | 搜索或 AI 问答后打开原文的用户比例 | ≥ 40% |
| 保证回答可信 | 带有效引用的回答占比 | ≥ 95% |
| 控制权限风险 | 跨租户、越权文档泄露事件 | 0 起 |
| 保证索引时效 | 文档保存至可检索的 P95 延迟 | ≤ 60 秒（1 MB 内文档） |
| 保证交互体验 | RAG 首个流式 Token 的 P95 延迟 | ≤ 3 秒（正常模型服务下） |
| 提升资料覆盖 | 成功同步的飞书资源占比 | ≥ 98% |
| 降低使用门槛 | 新租户完成首批文档导入的时间 | ≤ 10 分钟 |

### 2.6 首版非目标

以下能力不纳入 MVP，避免范围失控：

1. 多人实时协同编辑，不实现 OT/CRDT。
2. 飞书与平台的双向同步；首版只做飞书到平台的单向同步。
3. 模型训练、微调和自动构建企业专属大模型。
4. 原生移动端 App、小程序和离线客户端。
5. 计费、套餐、发票和在线支付。
6. 复杂工作流审批、知识图谱和自动生成报表。
7. LDAP、OIDC、企业微信等单点登录；接口层预留扩展点，V2 再实现。

## 3. 产品范围与版本规划

### 3.1 版本范围

| 版本 | 目标 | 包含能力 |
| --- | --- | --- |
| MVP | 跑通最小业务闭环 | 租户与登录、角色权限、目录与文档、版本、回收站、附件上传、飞书单向同步、全文搜索、RAG 问答、引用溯源、基础通知、Docker 部署 |
| V1.1 | 提升安全性、可运营性与体验 | 分享链接、文档 ACL 细分、索引补偿、同步重试、问答反馈、会话管理、监控看板、qiankun 微前端拆分、CI/CD |
| V2 | 企业增强 | 独立库租户、SSO、Webhook、多模型路由、知识库统计、批量导入、更多文件预览 |

### 3.2 MVP 核心业务闭环

1. 管理员创建租户并邀请成员。
2. 成员登录后创建文件夹和 Markdown 文档，或由管理员配置飞书同步。
3. 文档保存后自动进入切片、向量化和全文索引流程。
4. 成员在目录中搜索文档，或进入 AI 问答。
5. AI 检索候选片段后执行权限过滤，基于可见内容流式回答并给出引用。
6. 成员点击引用回到原文；管理员可在同步日志和索引状态中定位失败任务。

### 3.3 交付形式

| 形式 | 说明 |
| --- | --- |
| 多租户 SaaS | 一套服务承载多个企业租户，默认使用共享库共享表隔离 |
| 私有化部署 | 通过 Docker Compose 在企业内网部署，数据不离开客户环境 |
| 可选独立库 | 大型租户可配置独立 MySQL 数据库，V2 完成自动化开通与迁移；V1 保留配置模型 |

## 4. 角色、权限与关键业务规则

### 4.1 租户规则

1. 每个用户至少属于一个租户；首版一个账号只归属一个租户。
2. 所有业务表必须包含 `tenant_id`，任何查询不得跨租户读取。
3. 平台级管理员可创建、停用租户；租户管理员只能管理本租户。
4. 租户停用后，普通用户不可登录，后台任务停止执行，已有数据保留。
5. 租户内所有资源 ID 使用全局唯一 ID；不可仅依赖自增 ID 猜测资源。

### 4.2 角色与权限

系统预置以下角色模板，租户管理员可调整角色菜单权限：

| 角色 | 默认能力 |
| --- | --- |
| 租户管理员 | 租户配置、用户、角色、全部文档、飞书同步、系统通知 |
| 知识管理员 | 目录维护、文档管理、飞书同步、索引重建、查看同步日志 |
| 编辑者 | 创建和编辑自己有权限的文档、上传附件、发起 AI 问答 |
| 阅读者 | 阅读被授权文档、搜索、发起 AI 问答 |
| 外部访客 | 仅通过有效分享链接阅读指定文档，不进入搜索与 AI 问答 |

权限分为两层：

1. **功能权限**：是否可见菜单、按钮、接口，由 RBAC 控制。
2. **数据权限**：是否可读写某份文档，由租户、所有者、文档可见范围和 ACL 控制。

### 4.3 文档数据权限

1. 文档可见范围分为：私有、租户可见、指定对象可见。
2. 指定对象支持按用户和角色授权。
3. 文档所有者始终拥有读取、编辑、管理和删除权限。
4. 文件夹可配置默认权限，新建文档默认继承最近一级文件夹权限。
5. 文档显式配置 ACL 后，以文档 ACL 为准；租户管理员始终可管理。
6. 权限变更立即生效。搜索、AI 召回和文件下载都必须重新校验，不允许依赖缓存中的旧权限。
7. 分享链接只授予只读权限，可设置密码和过期时间；外部访客不得触发 AI 问答。

### 4.4 文档生命周期

```text
创建草稿 → 已发布 → 已归档/回收站 → 物理删除
                ↘ 新版本（保存版本）
```

| 状态 | 行为 |
| --- | --- |
| 草稿 | 仅创建者可见；可继续编辑；不进入检索索引 |
| 已发布 | 按权限可见；进入全文与向量索引 |
| 回收站 | 逻辑删除，默认保留 30 天；不参与搜索与 AI 召回 |
| 物理删除 | 删除文档、附件、版本、向量和 ES 索引，操作不可恢复 |

补充规则：

1. 文档离开“已发布”状态时，必须从 ES 和向量库删除对应索引。
2. 回收站恢复后重新进入索引流程。
3. 文档内容变化时以版本号作为索引幂等键，旧版本向量必须在成功后清理。
4. 版本恢复生成一个新版本，不覆盖历史记录。

### 4.5 飞书同步规则

1. 同步方向固定为飞书 → MZ-KnowBase，不支持平台反向写回飞书。
2. 支持飞书文档和飞书多维表格，其他类型记录为“不支持”并跳过。
3. 飞书来源文档在平台内只读，避免内容回写和冲突。
4. 每个租户独立配置飞书应用凭证、知识空间 ID 和同步范围。
5. 支持首次全量同步、每日增量同步和手动触发；同一租户同一时刻只能有一个同步任务。
6. 增量同步使用服务端记录的游标或上次成功时间；同步成功后推进游标。
7. 以 `source_type + source_id` 保证幂等；重复同步更新原文档，不重复创建。
8. 飞书侧删除或移出同步范围时，平台将对应文档移入回收站。
9. 单个资源失败不回滚整批任务，必须记录资源级错误并支持重试。
10. 附件在同步时复制到 MinIO；飞书原链接仅作为溯源信息保存。

### 4.6 AI 问答规则

1. 回答只能使用检索到的、当前用户有权访问的文档片段。
2. 没有足够证据时必须明确说明“知识库中未找到足够依据”，不得编造。
3. 每条回答至少返回 1 条引用；引用包含文档标题、片段摘要和可访问链接。
4. 引用链接打开前再次校验权限；权限已失效时提示无权访问。
5. 首版默认保留最近 10 轮会话上下文，超出后截断较早消息并提示。
6. 用户可对回答点赞或点踩；点踩原因进入运营数据，不直接自动训练模型。
7. 同一租户的会话与消息仅对会话所有者、租户管理员可见。
8. 敏感词命中时按配置拒绝提问或仅返回安全提示。
9. 外部访客、租户停用用户和未登录用户不得调用 AI 问答。

## 5. 功能需求

### 5.1 登录与账号

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-AUTH-001 | P0 | 用户使用账号和密码登录 | 正确凭证返回 JWT 与用户信息；错误凭证不暴露账号是否存在 |
| FR-AUTH-002 | P0 | 用户可退出登录 | 退出后旧 Token 立即失效，无法继续调用受保护接口 |
| FR-AUTH-003 | P0 | 租户管理员可创建、停用、重置用户 | 停用后该用户所有 Token 失效；历史操作记录保留 |
| FR-AUTH-004 | P0 | 登录后加载菜单和权限标识 | 无权限菜单不渲染，直接访问接口返回 403 |
| FR-AUTH-005 | P1 | 用户可修改自己的密码 | 修改后其他会话失效，当前会话可选择保留 |
| FR-AUTH-006 | P1 | 登录失败次数限制 | 连续失败 5 次后锁定 15 分钟，可被管理员解锁 |

### 5.2 租户与系统管理

| 编号 | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| FR-SYS-001 | P0 | 平台管理员创建租户 | 自动生成租户管理员账号、默认角色和基础目录 |
| FR-SYS-002 | P0 | 租户管理员维护用户与角色 | 可分配角色，角色变更后权限即时生效 |
| FR-SYS-003 | P0 | 菜单和按钮权限配置 | 权限标识可配置，前后端校验一致 |
| FR-SYS-004 | P0 | 租户配置 | 可维护租户名称、状态、Logo、默认语言和隔离模式 |
| FR-SYS-005 | P0 | 数据隔离模式 | 共享表模式强制注入 tenant_id；独立库模式展示为未启用或按版本启用 |
| FR-SYS-006 | P1 | 操作审计查询 | 支持按用户、时间、操作类型筛选文档和系统操作 |

| FR-DOC-002 | P0 | 创建 Markdown 文档 | 保存标题、正文、摘要、标签、可见范围；返回文档 ID |
| FR-DOC-003 | P0 | 编辑文档 | 支持自动保存草稿和手动发布；并发修改时提示版本冲突 |
| FR-DOC-004 | P0 | 文档列表与详情 | 支持分页、按目录、类型、更新时间筛选；无权限文档不返回标题等敏感元数据 |
| FR-DOC-005 | P0 | 文档版本 | 可手动保存版本、查看版本列表、预览和恢复；恢复生成新版本 |
| FR-DOC-006 | P0 | 回收站 | 删除进入回收站；支持恢复和彻底删除；30 天后自动清理 |
| FR-DOC-007 | P0 | 文档权限 | 支持私有、租户可见、指定用户/角色；权限变更后立即生效 |

| FR-DOC-012 | P2 | 富文本编辑器 | 支持表格、图片、代码块和引用；首版不阻塞 |

## 8. 非功能需求

### 8.1 性能

| 指标 | 要求 |
| --- | --- |
| 文档列表接口 | P95 ≤ 500 ms（10 万文档以内） |
| 全文搜索 | P95 ≤ 800 ms |
| 文件分片上传 | 500 MB 文件在网络正常时 10 分钟内完成 |
| 文档索引延迟 | 1 MB 内文档 P95 ≤ 60 秒 |
| RAG 首 Token | P95 ≤ 3 秒（不含模型排队极端情况） |
| RAG 完整回答 | P95 ≤ 30 秒 |
| 并发 | 首版支持 50 个在线用户、10 个并发 AI 问答 |

### 8.2 安全

1. 全链路必须传递并校验租户上下文，禁止客户端伪造租户 ID。
2. 密码使用 BCrypt 或 Argon2 哈希，禁止明文存储。
3. JWT 设置合理过期时间，退出登录使用 Redis 黑名单。
4. 飞书密钥、LLM 密钥加密存储，日志脱敏，接口不回显。
5. 文件下载使用短时效签名 URL，并校验文档权限。
6. AI 召回结果必须二次权限过滤，禁止只依赖向量库过滤。
7. 内部服务接口必须校验内部令牌，不能直接暴露公网。
8. 所有用户输入执行长度、类型和敏感词校验；Prompt 中明确隔离系统指令与文档内容。

### 8.3 可用性与可靠性

1. 核心服务目标可用性 99.5%。
2. 文档保存成功后不得因 MQ 或 AI 服务故障而丢数据。
3. MQ 消费失败进入死信队列，支持人工重放。
4. 飞书同步、索引构建、文件合并不允许同一业务对象并发执行。
5. 所有异步任务必须可重试、可观测、有幂等键。

### 8.4 兼容性

| 项目 | 要求 |
| --- | --- |
| 浏览器 | Chrome、Edge 最近两个大版本 |
| 分辨率 | 1366×768 及以上；管理后台优先桌面端 |
| 服务端 | Linux x86_64 / ARM64 容器环境 |
| 数据库 | MySQL 8.0 |
| 文件格式 | Markdown、TXT、PDF、DOCX、XLSX、PPTX、常见图片 |

### 8.5 可维护性

1. 服务间接口使用 OpenAPI 3 描述；Python 服务同样输出 OpenAPI。
2. 统一错误码、日志格式和 Trace ID。
3. 数据库变更使用版本化 SQL 脚本，禁止手工修改生产库。
4. 配置通过 Nacos 或环境变量注入，不写死在代码中。
5. 所有关键链路提供开发环境一键启动脚本。

## 9. 异常与边界场景

| 场景 | 预期行为 |
| --- | --- |
| 用户权限在问答过程中被收回 | 已生成内容不追加无权限引用；引用点击再次校验并提示无权访问 |
| LLM 超时或熔断 | 返回“服务繁忙”，保留已生成片段并标记未完成；记录失败指标 |
| 文档更新时旧索引删除失败 | 新版本索引成功后重试清理；补偿任务按版本号修复 |
| 飞书 API 限流 | 指数退避重试；持续失败记录资源级错误并告警 |
| 分片上传中断 | 支持断点续传；超时分片定期清理 |
| 同一文档多人同时编辑 | 使用版本号乐观锁；冲突时提示刷新或另存副本 |
| 向量库不可用 | 问答可降级为 ES 关键词召回，并在响应中标记降级状态；纯向量模式直接报错 |
| 搜索服务不可用 | AI 问答仍可使用向量召回；后台提示搜索降级 |
| 租户容量超限 | 阻止新增文档和上传，保留读取与删除能力，管理员可扩容 |
| 文件类型伪造 | 同时校验扩展名、MIME 和文件头，不通过则拒绝 |
| 用户输入 Prompt 注入 | 文档内容按不可信数据处理，系统提示明确禁止执行文档内指令 |

## 10. 验收标准

### 10.1 MVP 功能验收

1. 新租户可在 10 分钟内完成管理员登录、创建目录、创建文档、发布并获得可检索状态。
2. 两个租户互相不可见任何文档、用户、会话、文件和通知。
3. 普通成员只能搜索和问答到自己有权访问的文档。
4. 飞书全量同步与增量同步均可成功完成，重复执行不产生重复文档。
5. 文档更新后 60 秒内可被搜索和 AI 检索；删除后不再被召回。
6. AI 回答带可点击引用；无依据时不编造。
7. 500 MB 文件可断点续传并成功合并；无权限用户无法下载。
8. 服务重启后，未完成索引可由补偿任务恢复。
9. Docker Compose 可在干净环境启动全部依赖，健康检查通过。

### 10.2 安全验收

1. 伪造 `tenant_id` 请求无法读取其他租户数据。
2. 被停用用户的旧 JWT 无法继续访问。
3. 飞书与 LLM 密钥不出现在日志、接口响应和前端构建产物中。
4. 随机抽取无权限文档，AI 问答无法引用其任何正文片段。
5. 文件签名 URL 过期后无法访问。

### 10.3 交付验收

1. 代码仓库、初始化 SQL、配置模板、Docker 编排和启动说明齐全。
2. 核心接口有 OpenAPI 文档；核心模块有单元测试和至少一条集成测试。
3. 关键链路有 Trace ID，监控指标可被 Prometheus 采集。
4. 提供故障演练记录：MQ 堆积、LLM 超时、ES 不可用、向量库不可用。

## 11. 风险与依赖

| 风险/依赖 | 影响 | 应对 |
| --- | --- | --- |

| 手工编码范围过大 | 长期无法交付 | 严格按开发计划里程碑推进，每阶段可运行、可验收 |
